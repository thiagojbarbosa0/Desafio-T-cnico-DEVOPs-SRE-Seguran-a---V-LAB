## Alterações reais da R7

1. `backend/security_core.py`: tokens HMAC de demo rejeitam tamanhos excessivos, Base64 não-canônico, estrutura JSON com claims duplicados ou adicionais, expiração inválida e nonce malformado. Assinatura é conferida antes de parsear o payload. Não é um mecanismo Firebase.
2. `backend/demo_store.py`: quota SQLite sintética opera sob `BEGIN IMMEDIATE`; requisições recusadas não aumentam a contagem, relógio regressivo não reinicia a janela, estado corrompido falha fechado, entradas de configuração são validadas. Não é substituto do limiter Firebase RTDB de produção.
3. `backend/local_server.py`: rejeita `Transfer-Encoding`, `Content-Length` duplicado/ambíguo e request target absoluto; JSON com chaves repetidas e constantes não padronizadas `NaN/Infinity` é rejeitado; logs de exceções inesperadas omitem stack trace potencialmente sensível.
4. `tests/test_r7_session_and_quota.py`, `tests/test_r7_http_framing.py`, `tests/test_r7_gate_contract.py`: 43 testes adicionais, parte via HTTP real no servidor sintético.
5. `scripts/prove_r7_dual_replica_auth.py`: sobe **duas instâncias HTTP loopback** temporárias compartilhando um SQLite e segredo *sintético*, exercita autenticação entre réplicas, bloqueio BOLA, quota 30/31 e ausência de incremento após 429. Desliga todos os servidores no final; salva JSON sanitizado com SHA-256 de fonte.
6. `scripts/release_gate_work_v19_9.py`: associa a nova evidência sintética aos hashes atuais, exige todos os checks corretos e **atribui zero pontos extras**; não aceita evidência desatualizada.
7. `.github/workflows/ci.yml`: acrescenta os testes, prova das duas instâncias e upload da evidência sanitizada.

## O que NÃO foi comprovado

A stack Flask original não foi testada com Firebase Admin real nesta sessão; Firebase Auth/RTDB Emulator Docker, frontend completo `npm ci && build`, Prometheus+Grafana integrados, prova da quota original 20/21, atestado das imagens da V19.15 e cinco achados upstream/3 root causes continuam pendentes. Mesmo a prova HTTP R7 em duas instâncias usa **servidor demo + SQLite**, não o gateway Flask.

R6 exigia emuladores em endereços loopback: isso pode ser incompatível com DNS de serviços dentro de Docker. Na V19.15, preservar a configuração própria dos emuladores internos; não portar esse guarda R6 cegamente.
